GUIDANCE - Choosing DROP as Target for PREROUTING Packets Evaluated at raw Stage
( Target Cell: PRE_raw_t3 - dummy content for purposes of demonstration )

Core purpose, for using the DROP target in the raw table's PREROUTING chain, is
  • to discard malicious or unwanted packets
before consuming memory for connection tracking. By doing so, it limits the negative impact on CPU and Memory resources during DDoS attacks or high-traffic floods.

Core Scenarios for Early DROPing

Extreme DDoS / SYN Floods

Stopping volumetric packet floods at the earliest network driver hook prevents the kernel state table from filling up with half-open connection entries.

Bogon / Invalid IP Filtering

Dropping packets that arrive with unroutable, private, or reserved source IPs (e.g., RFC 1918 space on a public interface) before any processing occurs.

Stateless Edge Security on High-Bandwidth Routers

Implementing high-performance line-rate packet drops on heavy 10GbE+ interfaces where state tracking overhead is too expensive.

Pre-Routing Blacklisting

Discarding traffic from known malicious actors or active botnet IPs straight at the boundary before routing lookups or NAT evaluations take place.


Methods to Address Anticipated Scenarios

Extreme DDoS / SYN Floods

To mitigate high-volume SYN floods, you can pair the early DROP target with the limit or hashlimit module to allow legitimate traffic while dropping abusive volumetric spikes.

Sample form(s) of command: 

iptables -t raw -A PREROUTING \
	-p tcp --syn \
	-m hashlimit \
	--hashlimit-above 100/sec \
	--hashlimit-burst 150 \
	--hashlimit-mode srcip \
	--hashlimit-name syn_flood_limit -j DROP

This works because it tracks incoming SYN packets per source IP (srcip). If a single IP exceeds 100 SYN packets per second (with a burst 'headroom' of 150), any additional SYN packets from that IP are immediately dropped at the raw chain before they can consume limited resources.

Bogon / Invalid IP Filtering (WAN-facing Only)

Bogon IPs are addresses that should never appear on the public internet (such as private, loopback, or reserved subnets). If your server is connected to a public-facing interface (not your organization's private LAN), you should drop these instantly.

Sample form(s) of command: 

# Drop private RFC 1918 networks arriving on public eth0
iptables -t raw -A PREROUTING -i eth0 -s 10.0.0.0/8 -j DROP
iptables -t raw -A PREROUTING -i eth0 -s 172.16.0.0/12 -j DROP
iptables -t raw -A PREROUTING -i eth0 -s 192.168.0.0/16 -j DROP

# Drop loopback spoofing and APIPA/link-local autoconfiguration
iptables -t raw -A PREROUTING -i eth0 -s 127.0.0.0/8 -j DROP
iptables -t raw -A PREROUTING -i eth0 -s 169.254.0.0/16 -j DROP

# Drop multicast and reserved experimental spaces
iptables -t raw -A PREROUTING -i eth0 -s 224.0.0.0/4 -j DROP
iptables -t raw -A PREROUTING -i eth0 -s 240.0.0.0/4 -j DROP

It is important to note that many of the address ranges, being blocked for WAN-originating packets, are in fact ranges which are to be expected at your computer interface if the computer is on a private LAN, in which case it is strongly inadvisable to block these, except for special circumstances.

Stateless Edge Security on High-Bandwidth Routers

If your high-bandwidth server or router provides a specific stateless service (like public DNS over UDP) but should absolutely never accept traffic on high-traffic ports (like standard web servers or internal database servers), you can drop that traffic statelessly, in order to avoid wasting CPU cycles.

Sample form(s) of command: 

# Statelessly drop all incoming HTTP/HTTPS traffic
iptables -t raw -A PREROUTING -p tcp --dport 80 -j DROP
iptables -t raw -A PREROUTING -p tcp --dport 443 -j DROP

# Statelessly drop unapproved high-volume UDP ports
#   (e.g., custom game ports or NTP reflection vectors)
iptables -t raw -A PREROUTING -p udp --dport 123 -j DROP

Pre-Routing Blacklisting

When an external IP or subnet is actively attacking your infrastructure, scanning ports, or acting as a known botnet node, you can hard-ban them at the absolute perimeter.

Sample form(s) of command: 

# Drop a specific malicious single attacker IP
iptables -t raw -A PREROUTING -s 203.0.113.50 -j DROP

# Drop an entire rogue /24 subnet or hosting provider 
#   known for spam/attacks
iptables -t raw -A PREROUTING -s 198.51.100.0/24 -j DROP

Note that this is where each of Whitelists and Blacklists would be strategically managed using the ipset functionality of iptables.
